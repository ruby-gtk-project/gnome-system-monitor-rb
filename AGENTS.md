# gnome-system-monitor — Ruby port

This branch is the Ruby GTK4 / Libadwaita port of GNOME System Monitor. The
C/C++ original lives on this fork's `main` branch and is the spec — read it,
don't copy it. `README.md` covers what the app does and how to run it.

## Skills — use them

Two skills are installed in `.claude/skills/`. They are not optional reading.

- **ruby-gtk** — the house style for Ruby GTK4/Libadwaita: the declarative
  memoized-widget pattern, Adwaita binding quirks, worked examples. Load it
  before writing or reviewing ANY Ruby GTK code, including single widgets, and
  before planning a change to a view. The bindings are quirky enough that code
  written from memory is unreliable.
- **ruby-gtk-testing** — run the app headlessly and drive its UI: click through
  dialogs, assert widget state, capture screenshots. Use it before claiming any
  GTK change works. `ruby -c` and a successful `require` prove nothing about a
  UI.

## Setup

`direnv allow` (or `nix develop`) gets Ruby, GTK4, Libadwaita and the
introspection typelibs. Then `bundle install`.

Everything is run through the dev shell:

```sh
nix develop --command make test
nix develop --command bundle exec rubocop
nix develop --command env -u DISPLAY -u WAYLAND_DISPLAY bundle exec ruby test/drive_window.rb
```

`gemset.nix` is regenerated by `.envrc` (`bundix -l`) whenever `Gemfile.lock`
moves ahead of it.

## Before changing a table

Read the top of `lib/gnome_system_monitor/list_refresh.rb`. Two obvious ways
to keep a GtkColumnView's cells up to date are memory-corruption bugs under
these bindings, and the code is shaped the way it is to avoid both.
`test/test_binding_limits.rb` reproduces them.

## Style

`.rubocop.yml` plus the custom cops in `cops/` are enforced: no `return`, no
modifier `if`, no conditional assignment, `tap` where it applies, and fixed
multi-line argument/hash layout. Run `bundle exec rubocop` before committing.
